# Refleksi — Deployment Microservices dengan Docker Compose

Nama service pada URL `http://product-service:3000` digunakan karena setiap container berjalan pada lingkungan jaringan yang terpisah, sehingga `localhost` di dalam order-service hanya menunjuk ke container order-service itu sendiri; nama `product-service` diterjemahkan oleh DNS internal jaringan Docker Compose ke alamat container yang sesuai. Data stok dan pesanan pada aplikasi ini disimpan di memori, sehingga data kembali ke kondisi awal ketika container dibuat ulang; sistem nyata memerlukan penyimpanan persisten seperti database terkelola atau volume yang dirancang dengan benar. Menyimpan kredensial bawaan seperti `guest/guest` langsung di `docker-compose.yml` berisiko karena siapa pun yang memperoleh repository dapat menggunakannya untuk mengakses broker, terutama jika konfigurasi tersebut digunakan di lingkungan yang lebih luas. Karena itu, kredensial lokal disimpan di file `.env` yang tidak di-commit, sedangkan produksi sebaiknya menggunakan secret manager atau mekanisme secrets milik platform deployment dengan hak akses minimum dan rotasi berkala.
